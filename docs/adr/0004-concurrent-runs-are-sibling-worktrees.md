# 0004. Concurrent runs are sibling worktrees; git is the registry

Status: accepted (2026-07-29)

## Context
Two continuity scenarios: (a) a second dump arrives while a /ps-dormammu run is mid-flight, and should spec and build without waiting; (b) a shipped product gets fed new dumps over time, and each cycle should build on the existing PRODUCT/ROADMAP/STATE rather than restart. Forces: pstack's state is markdown in the repo, so two live runs mean two branches editing shared files (ROADMAP.md, STATE.md) and, worse, two agents mutating one working tree; a dependency across runs has no meaning until the other run's work is somewhere stable; a registry file (RUNS.md) naming active runs would need updating from branches that never touch main, so it would drift from reality; renumbering phases while a run holds their numbers breaks that run's world.

## Decision
One working tree hosts one run. A run is a branch named `ps/<slug>` (phase worktrees: `ps/<slug>/NN`); a second run — planning or building — moves itself to a sibling worktree cut from main before touching anything. Discovery derives from git alone: `git worktree list` + `ps/*` branches + reading a run branch's ROADMAP and specs yields every active run and its claims; no registry file exists to drift (rejected: RUNS.md). A `Depends on:` entry is satisfied only when its phase is done AND landed on main, or was built earlier in the same run — which makes cross-run blocking fall out of existing syntax: a phase that needs another run's unlanded work parks until that run ships. Surface overlap with an active run, absent a declared dependency, is treated as an implicit block — conservative by design. While any run is live, ROADMAP.md is append-only (new phases take fresh numbers; no renumbering, no revising a phase under a run's feet). STATE.md is never hand-merged across runs; at close it is regenerated by /ps-checkpoint. Runs land one at a time: /ps-close merges main into the run branch first, reconciles ROADMAP as a union of rows (each run authoritative for its own phases), and re-runs the full suite before the panel.

## Consequences
+ Concurrency is safe by construction — isolation comes from worktrees, not from coordination protocols; the registry cannot lie because it is derived; scenario (b) stays zero-ceremony (`/ps-start dump2.md` in the same tree when nothing is running); a landed run visibly unblocks the phases that waited on it.
- Cross-run dependents wait for a full land — no speculative stacking on unmerged branches; sibling worktrees cost disk and a session reopen on harnesses that can't leave their launch directory; append-only numbering during live runs can leave roadmap order less tidy until a quiet moment. Revisit if stacked-branch tooling matures enough to trust unlanded foundations.
