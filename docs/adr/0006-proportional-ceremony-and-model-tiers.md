# 0006. Proportional ceremony and model tiers

Status: accepted (2026-08-05)

## Context
The first full 2.2 dormammu run in the field (rm_ally_style, a five-phase prose-deliverable MVP) shipped a clean one-shot build — and spent 5h38m, 27 subagents, ~2.3M output tokens and ~158M cache-read tokens doing it, all on the session's frontier model at full reasoning effort. Two findings. First, the panel's cost is headcount, not judgment: three-plus fresh contexts per phase re-bought the same spec, diff, and corpus to return 12 verdicts with zero must-fixes; a further fresh "fix agent" re-bought a phase's entire context to apply twelve already-decided edits. Second, spawned agents had no output discipline: on the prose phase, agents drafted whole deliverables inside extended thinking and died at the 64k output-token cap — seven deaths, ~450k tokens for nothing, over two hours of the run — after which the conductor improvised the correct working rules (file-by-file, small edits, no restating files) in its resume messages. Options considered: keep the flat panel and raise the output cap (longer deaths, same waste); a runtime config file (yaml) for per-role model routing (a second config surface, a parse burden on non-Claude harnesses, and roles are the wrong key — the same role spans trivial to hard); or make weight, routing, and discipline part of the skills with one declarative line in the existing Capabilities map.

## Decision
Ceremony scales with risk, and models are assigned by task nature, never by role. /ps-review defaults to one combined fresh-context judge (all bars, one read); the split panel runs on explicit triggers (security surface, multi-surface diff, `Review: full`, a close over parked/flagged work, operator request). Panel must-fixes return to the phase's still-warm builder via resume — a fresh fix agent is the last resort. Every spawned pack ends with a standard output-discipline block (work file-by-file; never restate a file in prose or thinking; draft deliverables in the file incrementally; tool-call early), and overflow deaths are resumed with smaller work units, never respawned. Model selection is one `model-tiers` line in CLAUDE.md's `## Capabilities` — deep = session model (design, judging, prose craft, security) · standard (routine building) · mechanical (known fixes, recounts, delta re-checks) — read by the skills, set per spawn only where the harness allows, inert (and visible as such) where it doesn't. Specs may mark `Complexity: hard` and `Review: full`. Misclassification is made cheap instead of impossible: a failed or parked agent retries once one tier up, the mechanical gate re-runs after mechanical-tier work regardless, and manifest lines record weight and tier per agent so morning reports teach the tuning.

## Consequences
+ A run's cost tracks its risk: light phases pay one judge and no fix agent (the field run's shape re-priced: roughly half the tokens and hours); prose-heavy phases stop dying at the output cap; cheap models absorb mechanical work without touching the quality path (tests-first, fresh builder per phase, at least one independent fresh-context review, attended close).
- The conductor now classifies (weight, tier) and can misjudge — bounded by triggers forcing the split panel and deep tier on stakes, the one-tier-up retry, and the always-on gate; a light verdict carries less redundancy than three independent reads, accepted because the split panel remains one spec line away; `model-tiers` names concrete models and will need occasional refresh as the lineup churns (deep anchors to the session model deliberately, so the ceiling never goes stale). Revisit if morning reports show light panels leaking must-fixes that the split panel would have caught.
